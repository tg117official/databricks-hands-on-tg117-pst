1. The local OLTP-to-OLAP pipeline

Both databases run in the same local MySQL server. PySpark reads the OLTP tables through JDBC, changes their shape, and writes the star schema through JDBC.

Load style for this lesson: the target is cleared and rebuilt. This full-refresh approach keeps the first conversion easy to follow. Incremental loading and SCD logic belong in later sessions.

2. Create the OLTP source

The setup contains enough connected data for useful transformations and reports. Foreign keys protect every relationship.

3. Create the OLAP target

The OLAP tables are created before PySpark writes data. This keeps MySQL keys, constraints and data types under our control.

Target star schema

The fact table stays in the center because it stores the sales event and its numbers. Each dimension answers a different business question: who bought, what was bought, when it happened and how the order was placed.

Run 1A in MySQL Workbench - create four dimensions and one fact
MySQL
CREATE DATABASE ecomsphere_olap
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_unicode_ci;

USE ecomsphere_olap;

CREATE TABLE dim_customer
(
    customer_key        INT AUTO_INCREMENT PRIMARY KEY,
    customer_id         INT NOT NULL,
    customer_name       VARCHAR(100) NOT NULL,
    city                VARCHAR(80) NOT NULL,
    country             VARCHAR(80) NOT NULL,
    customer_status     VARCHAR(50) NOT NULL,

    CONSTRAINT uq_dim_customer_id UNIQUE (customer_id)
) ENGINE = InnoDB;

CREATE TABLE dim_product
(
    product_key   INT AUTO_INCREMENT PRIMARY KEY,
    product_id    INT NOT NULL,
    product_name  VARCHAR(150) NOT NULL,
    category_id   INT NOT NULL,
    category_name VARCHAR(100) NOT NULL,

    CONSTRAINT uq_dim_product_id UNIQUE (product_id)
) ENGINE = InnoDB;

CREATE TABLE dim_date
(
    date_key       INT PRIMARY KEY,
    full_date      DATE NOT NULL,
    day_number     INT NOT NULL,
    month_number   INT NOT NULL,
    month_name     VARCHAR(20) NOT NULL,
    quarter_number INT NOT NULL,
    year_number    INT NOT NULL,

    CONSTRAINT uq_dim_date_full_date UNIQUE (full_date)
) ENGINE = InnoDB;

CREATE TABLE dim_channel
(
    channel_key  INT AUTO_INCREMENT PRIMARY KEY,
    channel_code VARCHAR(30) NOT NULL,
    channel_name VARCHAR(60) NOT NULL,

    CONSTRAINT uq_dim_channel_code UNIQUE (channel_code)
) ENGINE = InnoDB;

CREATE TABLE fact_sales
(
    sales_key          BIGINT AUTO_INCREMENT PRIMARY KEY,
    order_item_id      INT NOT NULL,
    order_id           INT NOT NULL,
    customer_key       INT NOT NULL,
    product_key        INT NOT NULL,
    date_key           INT NOT NULL,
    channel_key        INT NOT NULL,
    quantity           INT NOT NULL,
    unit_price         DECIMAL(12,2) NOT NULL,
    gross_sales_amount DECIMAL(14,2) NOT NULL,
    discount_amount    DECIMAL(14,2) NOT NULL,
    net_sales_amount   DECIMAL(14,2) NOT NULL,

    CONSTRAINT uq_fact_sales_order_item UNIQUE (order_item_id),
    CONSTRAINT chk_fact_sales_quantity CHECK (quantity > 0),

    CONSTRAINT fk_fact_customer
        FOREIGN KEY (customer_key) REFERENCES dim_customer(customer_key),
    CONSTRAINT fk_fact_product
        FOREIGN KEY (product_key) REFERENCES dim_product(product_key),
    CONSTRAINT fk_fact_date
        FOREIGN KEY (date_key) REFERENCES dim_date(date_key),
    CONSTRAINT fk_fact_channel
        FOREIGN KEY (channel_key) REFERENCES dim_channel(channel_key)
) ENGINE = InnoDB;

4. Business decisions used in the model

The code follows these decisions. If a business decision changes, the transformation must also change.

Process: product salesThe fact measures products sold through valid orders.
Grain: one order itemOne fact row represents one order_item_id.
Revenue statusesOnly PAID, SHIPPED and DELIVERED orders enter the fact.
Payment is excludedOne order can have many payment attempts. Payment needs a different fact and grain.
Customer dimensionOne row per current customer. Customer status text is flattened into the dimension.
Product dimensionOne row per product. Category fields are flattened to reduce reporting joins.
Date dimensiondate_key uses yyyyMMdd. Calendar fields are prepared once.
Channel dimensionOne row per controlled sales channel.
Surrogate keysMySQL generates customer, product and channel keys. PySpark reads them back for the fact lookup.
Order IDorder_id stays in the fact as a degenerate dimension for order tracing.
Additive measuresQuantity, gross sales, discount and net sales can be summed across fact rows.
Unit priceUnit price is useful at line level, but it should not normally be summed.
One fact_sales row = one eligible order_item row
OLTP inputOLAP outputTransformation decision
customer + customer_statusdim_customerReplace the status code with useful status text.
product + categorydim_productFlatten the product hierarchy for reporting.
Distinct orders.order_datedim_dateCreate reusable calendar fields.
order_channeldim_channelKeep one controlled row per channel.
orders + order_itemfact_salesFilter revenue statuses and calculate measures at order-item grain.
paymentNot loaded hereKeep the payment-attempt grain separate from product sales.

Run 2B in the PySpark shell - imports, password and JDBC helpers
PySpark
from getpass import getpass
from pyspark.sql import functions as F
from pyspark.sql.types import DecimalType

MYSQL_HOST = "localhost"
MYSQL_PORT = "3306"
MYSQL_USER = "root"
MYSQL_PASSWORD = getpass("Enter the local MySQL password: ")
MYSQL_DRIVER = "com.mysql.cj.jdbc.Driver"

def mysql_url(database_name):
    return (
        f"jdbc:mysql://{MYSQL_HOST}:{MYSQL_PORT}/{database_name}"
        "?useSSL=false"
        "&allowPublicKeyRetrieval=true"
        "&serverTimezone=UTC"
    )

def read_mysql(database_name, table_name):
    return (
        spark.read
        .format("jdbc")
        .option("url", mysql_url(database_name))
        .option("dbtable", table_name)
        .option("user", MYSQL_USER)
        .option("password", MYSQL_PASSWORD)
        .option("driver", MYSQL_DRIVER)
        .load()
    )

def write_mysql(dataframe, database_name, table_name):
    (
        dataframe.write
        .format("jdbc")
        .option("url", mysql_url(database_name))
        .option("dbtable", table_name)
        .option("user", MYSQL_USER)
        .option("password", MYSQL_PASSWORD)
        .option("driver", MYSQL_DRIVER)
        .option("batchsize", "1000")
        .mode("append")
        .save()
    )

print(spark.version)
print(mysql_url("ecomsphere_oltp"))
If the connection fails: confirm that MySQL is running on port 3306, the password is correct, and the connector was shown in the PySpark startup messages.

8. Build and validate the sales fact

Fact decisions applied in code

  • Keep only PAID, SHIPPED and DELIVERED orders.
  • Keep exactly one row per order_item_id.
  • Look up customer, product, date and channel keys.
  • Keep order_id directly in the fact.
  • Calculate gross, discount and net values once.
  • Do not join payment attempts.
Run 5A in the PySpark shell - join dimensions and build fact_sales
PySpark
fact_lookup_df = (
    eligible_items_df.alias("e")
    .join(
        dim_customer_db.alias("dc"),
        F.col("e.customer_id") == F.col("dc.customer_id"),
        "left"

    F.col("e.quantity") * F.col("e.unit_price")

Validate before writing

A failed check stops the load. This prevents incomplete or multiplied fact data from reaching MySQL.

Run 5B in the PySpark shell - execute all fact checks
PySpark
source_fact_rows = eligible_items_df.count()
fact_rows = fact_sales_stage.count()

duplicate_order_items = (
    fact_sales_stage
    .groupBy("order_item_id")
    .count()
    .filter(F.col("count") > 1)
    .count()
)

missing_dimension_keys = (
    fact_sales_stage
    .filter(
        F.col("customer_key").isNull()
        | F.col("product_key").isNull()
        | F.col("date_key").isNull()
        | F.col("channel_key").isNull()
    )
    .count()
)

source_totals = eligible_items_df.agg(
    F.sum(
        F.col("quantity") * F.col("unit_price")
    ).cast(DecimalType(14, 2)).alias("gross_sales"),
    F.sum("discount_amount").cast(
        DecimalType(14, 2)
    ).alias("discount"),
    F.sum(
        (F.col("quantity") * F.col("unit_price"))
        - F.col("discount_amount")
    ).cast(DecimalType(14, 2)).alias("net_sales")
).first()

fact_totals = fact_sales_stage.agg(
    F.sum("gross_sales_amount").alias("gross_sales"),
    F.sum("discount_amount").alias("discount"),
    F.sum("net_sales_amount").alias("net_sales")
).first()

measure_mismatches = (
    fact_sales_stage
    .filter(
        (F.col("gross_sales_amount") - F.col("discount_amount"))
        != F.col("net_sales_amount")
    )
    .count()
)

checks = {
    "source_fact_rows": source_fact_rows == 30,
    "source_and_fact_row_counts_match": source_fact_rows == fact_rows,
    "no_duplicate_order_items": duplicate_order_items == 0,
    "no_missing_dimension_keys": missing_dimension_keys == 0,
    "gross_sales_match": source_totals["gross_sales"] == fact_totals["gross_sales"],
    "discounts_match": source_totals["discount"] == fact_totals["discount"],
    "net_sales_match": source_totals["net_sales"] == fact_totals["net_sales"],
    "measure_formula_is_valid": measure_mismatches == 0
}

for check_name, passed in checks.items():
    print(check_name, "PASS" if passed else "FAIL")

print("Source totals:", source_totals.asDict())
print("Fact totals:", fact_totals.asDict())

failed_checks = [
    check_name
    for check_name, passed in checks.items()
    if not passed
]

if failed_checks:
    raise ValueError(f"Fact load stopped. Failed checks: {failed_checks}")

print("All checks passed. The fact is ready to load.")

SELECT 'dim_customer' AS table_name, COUNT(*) AS row_count FROM dim_customer
UNION ALL SELECT 'dim_product', COUNT(*) FROM dim_product

    SUM(discount_amount) AS discount,
    SUM(net_sales_amount) AS net_sales

SELECT COUNT(*) AS missing_dimension_keys
FROM fact_sales AS fs
LEFT JOIN dim_customer AS dc
    ON fs.customer_key = dc.customer_key
LEFT JOIN dim_product AS dp
    ON fs.product_key = dp.product_key
LEFT JOIN dim_date AS dd
    ON fs.date_key = dd.date_key
LEFT JOIN dim_channel AS dch
    ON fs.channel_key = dch.channel_key
WHERE dc.customer_key IS NULL
   OR dp.product_key IS NULL
   OR dd.date_key IS NULL
   OR dch.channel_key IS NULL;

SELECT COUNT(*) AS duplicate_order_items

    SELECT order_item_id
    FROM fact_sales
    GROUP BY order_item_id
    HAVING COUNT(*) > 1

  • Customer status is flattened into dim_customer.
